# Adaptive Defense: Zero-Day Attack Detection in NIDS With Deep Reinforcement Learning

## Project status

Implementation report for an offline research prototype. Synthetic demonstration results are generated by the software. Real UNSW-NB15 results remain pending dataset acquisition and experiment execution. This report must not be submitted as evidence of completed real-data experiments.

## Abstract

This project implements an adaptive network intrusion detection prototype that combines a deep autoencoder with a Deep Q-Network controller. A benign-trained autoencoder estimates reconstruction errors for network-flow records. A controller changes the decision threshold over replayed traffic windows using previous score statistics, past alerts, threshold history, and optionally delayed development feedback. The implementation compares the approach with Random Forest, a supervised multilayer perceptron, a fixed-threshold autoencoder, and a simple adaptive rule. Attack categories are withheld from development to assess unfamiliar-category detection. A separate adaptation partition permits policy updates before an untouched final evaluation. Metrics include recall, precision, F1, benign false positive rate, category-level recall, and confusion counts. The system includes a reproducible CLI, data-integrity tests, saved inference artifacts, and an interactive dashboard. Withheld-category evaluation is a proxy for unfamiliar attacks and does not prove real-world zero-day detection.

## 1. Problem and motivation

Signature-based intrusion detection depends on previously characterized patterns. Learning-based approaches can model traffic behavior but can also miss unfamiliar attacks or produce excessive alerts. This project studies whether a learned threshold controller improves the detection–false-alarm trade-off of a deep anomaly detector. It is not assumed that reinforcement learning is superior to a simpler rule.

The research questions are: (1) how much attack-category generalization does the anomaly model exhibit; (2) whether learned threshold control improves weighted detection cost; and (3) how feedback on separate records changes later performance. An honest negative result is valid.

## 2. Related work and foundations

UNSW-NB15 provides prepared network-flow records for intrusion detection research. The official prepared partitions have 175,341 and 82,332 records; this implementation deliberately constructs custom partitions when supplied those files. Refer to the official dataset page for provenance, schema and academic citation conditions.

DQN combines a neural action-value estimator with replay memory and a target network. The official PyTorch tutorial provides a reference for these mechanisms. Published intrusion detection work has used DQN for adaptive classification and active sample selection. This implementation instead makes threshold movement the discrete control action. Its contribution is an inspectable student-scale implementation and controlled comparisons, not a claim of a novel algorithm or state-of-the-art performance.

## 3. Functional requirements

The application must load compatible labeled flow CSVs, validate metadata, establish disjoint partitions, fit transformations without evaluation leakage, train an anomaly model, train a threshold controller, run baselines, evaluate frozen/adapted models, save configuration and artifacts, and expose results and compatible CSV inference through a dashboard.

Nonfunctional requirements include deterministic seeds where supported, actionable input errors, refusal to overwrite completed experiments, no label use during inference, and visible synthetic-data labeling. The prototype is CPU-oriented; no cloud account or GPU is required for its demo.

## 4. Architecture

```text
Flow CSV -> validation and feature fingerprints -> custom partitions
          -> training-fitted preprocessing -> benign autoencoder
          -> reconstruction scores -> threshold comparison -> alerts
Previous window statistics -> DQN -> next threshold adjustment
Separate development feedback -> reward -> controller updates
Untouched final data -> evaluator -> metrics / dashboard
```

The modules are data.py (schema/splits), models.py (networks/optimization), environment.py (window transition/reward), experiment.py (orchestration/artifacts), and dashboard.py (local UI/inference).

## 5. Dataset and preprocessing protocol

Required target metadata are label (0 normal, 1 attack) and attack_cat. IDs, target columns, raw endpoint IPs, selected timestamps and internal metadata are excluded from model features. Numerical columns use median imputation and standardization. Categorical columns use most-frequent imputation and one-hot encoding with unseen values ignored. All fitted transformations see training rows only.

Feature fingerprints support deduplication and saved membership manifests. Conflicting binary labels for identical features cause a failure for manual resolution. Known categories use 60/15/10/15 percent training/validation/adaptation/test allocation. Held-out categories use 0/0/40/60 percent. At least twenty unique records per category are required. The feature-level audit does not prove session-level independence or remove all correlated records.

The prepared input files are combined and repartitioned; no claim of official-split benchmark comparability is made. Randomized replay does not establish chronology or realistic concept drift. The demo generates four artificial categories with overlapping numeric distributions and random protocol fields. It is only a software fixture.

## 6. Deep anomaly model

The dense architecture is d -> 128 -> 64 -> 16 -> 64 -> 128 -> d, with ReLU hidden activations and a linear bottleneck/output. The loss is mean squared reconstruction error. Adam uses learning rate 0.001 and batches of 256. Training is restricted to benign training records. Benign validation reconstruction loss selects the best epoch, with patience eight. The maximum epoch count is configurable.

The anomaly score is e(x) = sum_j (x_j - reconstructed_x_j)^2 / d. A record is flagged when e(x) exceeds the threshold. This score is not a probability. Anomalies may be benign and attacks may reconstruct well. Equal MSE weighting of one-hot and numeric features is a simplification; feature-group weighting is future work.

Twenty-one candidate thresholds are derived from benign validation score quantiles between 0.80 and 0.999. The fixed baseline selects the threshold minimizing development weighted error. No threshold is tuned on final labels.

## 7. Reinforcement learning formulation

The state has eight entries: normalized threshold index, previous-window mean score, previous-window 95th-percentile score, previous alert fraction, previous action offset, delayed false-negative fraction, delayed false-positive fraction, and a feedback-available flag. Score summaries are scaled against the grid maximum and clipped. The initial state contains no traffic labels or current-window information.

Actions move down one threshold, stay, or move up one threshold. Movement is bounded by the threshold grid and persists. An action is chosen before scoring the next window. Previous-window summaries are then computed. Feedback, when enabled, becomes available only after that window's predictions.

Reward: r = -(5 FN + FP) / N. The false-negative multiplier is an explicit modeling choice; it is not an empirically validated operational cost. It should be varied in a future sensitivity experiment. Windows use configurable sizes, default 256; the small demo uses 64. Each replay pass is an episode and marks the final transition terminal.

The Q-network has layers 8 -> 64 -> 64 -> 3. It uses Adam at 0.0003, Huber loss, batch size 64, replay capacity 20,000, discount 0.95, gradient norm clipping at 1.0, and target copies every 500 updates. Epsilon declines from 1.0 to a floor of 0.05. Training alternates episodes with and without delayed feedback, so label-free evaluation is represented during development. Validation weighted error selects the policy checkpoint. The target copy is synchronized to the chosen checkpoint before adaptation.

The environment provides a constrained sequential control problem because actions change the threshold state reachable in later windows. However, the exogenous traffic stream is not affected by actions, and stationary shuffled traffic may make one fixed threshold optimal. This is a substantive limitation, not evidence that reinforcement learning must help. An analyst budget and realistic chronological drift would strengthen a future formulation.

## 8. Adaptation protocol

Clone the selected DQN. Keep the autoencoder, preprocessing and threshold grid fixed. Permit the clone to train on separate adaptation records with delayed feedback. Retain its development replay memory, reset its optimizer, and use a fixed configured number of adaptation passes (default three). Replaying records is offline retraining, not newly arriving independent feedback on each pass.

Evaluate both frozen and adapted policies from reset states on the same final records, with feedback disabled and no learning. Final labels are used only to calculate metrics. Once the adaptation partition exposes a category, the adapted policy's recall on it must be called post-adaptation category recall. It is not an untouched zero-day result. Only DQN receives the additional adaptation training in the current comparison; this is a before/after DQN experiment, not a fair adaptive-algorithm superiority claim over all baselines.

## 9. Baselines and metrics

Random Forest uses 100 trees, maximum depth 18 and balanced class weights. The supervised MLP uses hidden layers 64 and 32 with internal early stopping. Both use training data only. The autoencoder baseline uses a development-selected fixed threshold. The rule controller raises the threshold above a previous alert fraction of 10%, lowers it below 2%, and otherwise holds. These rule settings are predefined, not selected using test labels.

Precision = TP/(TP+FP); recall = TP/(TP+FN); F1 is their harmonic mean; false positive rate = FP/(FP+TN). Undefined precision/recall use zero according to the metric library configuration. Known recall and held-out-category recall are separate. Confusion counts permit independent metric checking. The dashboard's normal-category alert fraction is the false positive rate; attack-category alert fractions are recall.

Execution time in summary.json is whole-run duration, not inference latency. The current implementation does not claim measured production throughput or latency. Report at least three seeds for real experiments, including variability. A threshold trace or reward improvement alone is not proof of detection improvement.

## 12. Limitations and future work

Limitations include old benchmark traffic, synthetic ordering, no session-level isolation guarantee, reliance on verified training/adaptation feedback, MSE reconstruction assumptions, small threshold action space, no explicit analyst budget, and no live packet-to-feature pipeline. Labels may be noisy, benign behavior can drift, and inference input schemas must match training. The current dashboard makes no attack confidence or CVE attribution claim.

Useful extensions are chronological capture-group evaluation, explicit feedback-delay experiments, equal-feedback adaptive baselines, reward sensitivity, multiple held-out categories and random seeds, robust feature normalization, calibration, per-feature reconstruction analysis, inference timing, and a separately validated live feature extractor. No blocking or firewall automation is necessary for the academic demonstration.

## 13. Conclusion

The project supplies a complete offline experimental workflow for studying autoencoder anomaly detection with learned threshold control. Its academic value depends on transparent evaluation and comparison, not an assumed DQN advantage. Real-data evidence must be collected before making claims about unfamiliar network attacks.
